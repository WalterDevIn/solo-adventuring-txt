# Plan de la primera etapa del frontend

## Objetivo

Construir un cliente JavaScript vanilla navegable y demostrable sin implementar backend, parser, ECS, reglas de combate, persistencia ni red real.

## Sectores

### A. Fundación

- fundación del cliente;
- shell de aplicación;
- router y navegación;
- base visual y tokens.

### B. Núcleo narrativo

- modelo visual de mensajes;
- feed con hasta veinte mensajes visibles y scroll;
- cola de presentación;
- dados simples y enfrentados;
- highlight semántico;
- detalles técnicos expandibles.

### C. Pantalla de juego

- chat como superficie principal;
- input de una línea;
- historial con flechas arriba y abajo;
- aclaraciones;
- etiquetas e indicadores;
- popovers semánticos;
- modos narrativo, técnico y depuración.

### D. Catálogos y creación

- listas y detalles;
- personaje;
- criatura;
- raza;
- trasfondo;
- clase;
- objeto;
- conjuro.

### E. Preparación y sala

- configuración visual de combate;
- selección de participantes;
- controladores y relaciones;
- sala multijugador visual.

### F. Cierre

- responsive;
- audio;
- recorrido completo de demostración;
- revisión arquitectónica y visual.

## Regla de planificación

Los sectores indican orden y alcance general, no contratos irrevocables.

El planificador puede dividir, combinar o insertar correcciones según el estado real del código. No puede omitir decisiones de producto ni adelantar backend o simulación.

Cada contrato debe dejar un resultado demostrable, ser pequeño y declarar un nivel de verificación proporcional.
